# nestegg-backend

Backend for **nestegg**, a personal tracker for investments of any kind (securities, collectibles, real estate, cash). Prices are entered manually and their history is shown as a chart in the clients.

This repository contains the REST API. Web and mobile clients live in separate repositories.

## Status

Early development. The REST API for assets and prices is available. Authentication and deployment are not yet in place.

## Tech stack

- Kotlin, Java 25
- Spring Boot 4 (Web MVC, Data JPA, Validation, Actuator)
- PostgreSQL 18, schema managed by Flyway
- springdoc-openapi for the API specification
- JUnit 5, Testcontainers, MockK
- Gradle (Kotlin DSL)

## Key decisions

- **Spring Boot + PostgreSQL.** The data is relational and numeric (assets, price histories, later aggregations), which suits a relational database.
- **Flyway owns the schema.** Hibernate only validates the entities against it (`ddl-auto: validate`). Schema changes are made exclusively through new migrations in `src/main/resources/db/migration`; applied migrations are never edited.
- **Prices are unit prices.** `price_point.unit_price` is the price of a single unit. Position values are calculated as quantity × unit price and are never stored.
- **Prices are timestamped.** Each price point has a `recorded_at` timestamp, so several prices per day are possible. Timestamps in the future (beyond a few minutes of clock tolerance) are rejected.
- **Prices are strings in JSON responses** (e.g. `"340.5"`), so JavaScript clients do not lose precision. Requests accept numbers or strings.
- **Errors use ProblemDetail** (RFC 9457), with a list of invalid fields for validation errors.
- **Exact decimals for money.** Prices use `numeric` in the database and `BigDecimal` in code, never floating point types.
- **UUID identifiers**, generated by the application.
- **Asset types are an enum** stored as text, so new types can be added without a migration.
- **OpenAPI as the contract.** Clients generate their API code from the specification published by the backend.
- **Separate repositories** for backend, web and mobile.

## Getting started

### Prerequisites

- JDK 25
- Docker Desktop, running

### Run the application

```sh
./gradlew bootRun
```

On startup, Spring Boot starts the PostgreSQL container defined in `compose.yaml` and connects to it automatically. Flyway then applies all pending migrations.

The application runs on `http://localhost:8080`:

- Health check: `http://localhost:8080/actuator/health`
- OpenAPI specification: `http://localhost:8080/v3/api-docs`
- Swagger UI: `http://localhost:8080/swagger-ui.html`

### Run the tests

```sh
./gradlew test
```

Tests start their own disposable PostgreSQL container via Testcontainers and do not touch local development data.

### Reset the local database

Stop the application, then remove the container together with its data:

```sh
docker compose down -v
```

The schema is recreated on the next `bootRun`.

### Configuration

Allowed CORS origins for browser clients are set in `application.yaml` under `nestegg.cors.allowed-origins`. The default is `http://localhost:5173`, the Vite dev server.

## API

All endpoints live under `/api/v1`. The full specification is available in Swagger UI while the application runs.

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/assets` | List assets, newest first |
| `POST` | `/assets` | Create an asset |
| `GET` | `/assets/{assetId}` | Get an asset |
| `PUT` | `/assets/{assetId}` | Replace an asset |
| `DELETE` | `/assets/{assetId}` | Delete an asset and its prices |
| `GET` | `/assets/{assetId}/prices` | List prices, oldest first |
| `POST` | `/assets/{assetId}/prices` | Add a price |
| `GET` | `/assets/{assetId}/prices/{priceId}` | Get a price |
| `PUT` | `/assets/{assetId}/prices/{priceId}` | Replace a price |
| `DELETE` | `/assets/{assetId}/prices/{priceId}` | Delete a price |

Error responses: `400` for invalid input or prices in the future, `404` for unknown assets or prices.

## Project structure

Code is organised by feature:

```
src/main/kotlin/io/siffert/nestegg/backend/
├── asset/          Asset entity, repository, service, controller and DTOs
├── price/          Price point entity, repository, service, controller and DTOs
└── common/         Exception bases, global exception handler, CORS configuration
src/main/resources/
├── application.yaml
└── db/migration/   Flyway migrations
docs/               Learnings and planned integrations
```
